## Deviations from the brief

- The brief describes upstream as walking the file tree; upstream actually compares `p.toAbsolutePath()` with
  `p.toFile().getCanonicalPath()` (both cut after the last `shaders/`). On Linux that never folds case (the mismatched
  file simply does not exist and upstream reports a bare "file not found") and it resolves symlinks (a symlinked include
  would be reported missing). Demonica implements the walk the brief describes: a per-segment, case-insensitive
  resolution against cached directory listings. Message text is upstream's.
- The brief says upstream has no zip gate; it has one (`isZip`, threaded Iris.loadExternalShaderpack -> ShaderPack ->
  IncludeGraph, needed because `toFile()` throws on a zip FileSystem). D's ShaderPack has no flag, so IncludeGraph derives
  it from `root.getFileSystem() != FileSystems.getDefault()`; the `// Demonica:` comment explains why the gate stays for
  the listing walk (zip entry names match case-sensitively on every OS).
- Upstream's constructor signature `(root, startingPaths, isZip)` was not adopted; D keeps `(root, startingPaths)` plus a
  package-private overload taking the debug-options boolean.
- Zip test uses `FileSystems.newFileSystem(zip, (ClassLoader) null)` on a temp zip (no jimfs dependency).
- The check also runs on starting paths, as upstream (a mismatch there would surface as upstream's
  "unexpected error: failed to read" RuntimeException; starting names come from exact directory listings, so this only
  matters for odd dimension-folder spellings on case-insensitive file systems).
