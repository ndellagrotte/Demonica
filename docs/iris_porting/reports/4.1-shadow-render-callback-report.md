## Deviations from the brief

- **GL state.** The shadow model-view is pushed onto GLSM's model-view stack and RenderingState around the callbacks; upstream only sets the phase. 1.12.2 callbacks draw through the fixed-function matrices, and BSL's shadow.vsh uses `ftransform()`. The brief asked for the state to be documented, and this makes "GLSM's matrix stacks loaded with the shadow matrices" true. The probe confirmed it.
- **Placement.** The callbacks run after D's viewport reset; upstream resets the viewport after them. This guarantees a full-map viewport.
- **Render origin.** It is `Camera.getEntityPos()`, the eye position: the centre of D's shadow model-view and of its entity pass. Upstream passes the camera position, which differs from the eye position in third person.
- **Javadoc.** Besides the RenderPipeline paragraph, upstream's sentence that any render target may be passed when creating a render pass was dropped too. It describes render passes, which 1.12.2 lacks, and would be false in D.
- **Revision.** It is 2 (D's 1 + 1), not upstream's 4. Both javadocs say `@since Demonica API v0.2 (upstream Iris: API v0.4)`.
- **Test hook.** `ShadowRenderCallbacks.clear()` is package-private and exists only for the unit test.
- **Phase test.** A `TerrainPhaseScope.runCutout` helper and a test for it were added, beside the existing runOpaque/runTranslucent.
- **Probe commit.** The probe is committed in the diagnostics companion, which the brief allowed. Its script lives in run/ and is not committed.

## Open questions

- Mods written against upstream Iris may check `getMinorApiRevision() >= 4` before calling `registerShadowRenderCallback`. On Demonica that check fails, because Demonica reports revision 2. Should Demonica report upstream's number, even though it lacks revisions 1-3's methods? The brief said D's current revision + 1, which is what landed.
- Callbacks cannot be unregistered, as upstream. A pack reload keeps them, which is fine because they are static and pipeline-independent.
- The callbacks run inside Celeritas's `RenderDevice.enterManagedCode()` section, as entities do. A callback that changes raw GL state and does not restore it (blend, depth mask, bound texture) leaks that state into the entity draws. Upstream has the same exposure; nothing guards it.
