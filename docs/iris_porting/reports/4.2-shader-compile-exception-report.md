## Deviations from the brief

- The probe uses an undeclared identifier, not a syntax error: a syntax error is rejected by the glsl-transformer parser
  before the driver sees the source (run 3 above), so it cannot show the driver message.
- The chat line is the existing `iris.shaders.pipelineFailed` ("Failed to create the shader rendering pipeline, shaders
  disabled! Reason: ..."), not a "Failed to load" line: compile errors happen at pipeline creation, not in
  `loadExternalShaderpack` (which only parses the pack and never compiles; no catch was added there).
- Besides the three named sites, the upstream pass-throughs in CompositeRenderer, FinalPassRenderer, the
  DeferredWorldRenderingPipeline computes, ShadowCompositeRenderer and DHCompat were ported, so the exception reaches
  Iris unwrapped; and `findIn` covers Demonica's own wrapper.
- Departure from upstream text: the `(String, String)` constructor (double file name), plus `toLogLine`/`findIn`.
- Log text: "Shader compilation failed, see log for details", "Shader program linking failed, see log for details",
  "Failed to compile <TYPE> shader for program ..." and (for composite/final/compute) "Shader compilation failed!" no longer
  appear for compile/link failures; the new one-liner starts "Shader compilation failed for", so `Shader compilation failed`
  greps still match, `Failed to compile` greps no longer do. Recorded in the plan bullet.
- No section 11 "Open checks" entry exists for 4.2, so none was answered.
