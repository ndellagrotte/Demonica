# S10: the pack's layers and block contexts in the meshing loop

Draft, not sent. Replaces two injectors of `seam.ChunkBuilderMeshingTaskMixin`
(group MESHING).

## Problem

forge122's `ChunkBuilderMeshingTask.execute` meshes each block in every layer
`Block.canRenderInLayer` accepts, either through the fast block renderer or through
vanilla's `BlockRendererDispatcher.renderBlock` into a per-layer `BufferBuilder`
(`ChunkBuilderMeshingTask.java:116-126`). A shader pack needs two things from this
loop that it cannot get:
- **Its render layers.** A pack's block.properties can move a block to another
  layer (`layer.*`). The block must then render in that layer only.
- **The block behind each quad.** The pack's programs read the block's ID from
  block.properties (`mc_Entity`), its light and its position in the section
  (`at_midBlock`) from each vertex. Quads that take the vanilla path reach
  Celeritas as raw vertex data in a `BufferBuilder`
  (`VintageChunkBuildContext.copyBlockData`, S11), which says nothing about the
  block that drew them.

The modern loaders give their own block and fluid renderers this data
(`BlockRenderer` calls `ContextAwareChunkVertexEncoder.prepareToRenderBlockFace`).
forge122's vanilla path has no such hook.

## Proposal

- A provider hook for the layer, consulted before `canRenderInLayer`:
  `@Nullable Object renderLayerOverride(Block block)`.
- Around the vanilla-path `renderBlock`, a way to attach per-block data to the
  quads it draws: provider calls `beginVanillaBlock(state, pos, world)` and
  `endVanillaBlock()`, with Celeritas recording which quads of the layer's
  `BufferBuilder` each block drew and handing that to `copyBlockData` (S11).

Recording by quad index matters. Other code can draw into the same buffers
between two blocks, such as upstream's `FluidloggedCompat.renderFluidState` or
another mod's wrapper around `renderBlock`, and must not shift the data of the
quads after it. Demonica's `QuadContextRecorder` gives every finished quad an
entry, and a null one when no context was attached.

## What Demonica drops

The `@WrapOperation`s on `canRenderInLayer` and on the vanilla `renderBlock`, and
the task-local check of whether the build targets the shader passes. The capture in
vanilla's `BufferBuilder` (`BufferBuilderMixin`, not a quarantine patch) goes too
if Celeritas records the contexts itself.
