# C2: per-section chunk animations

Draft, not sent. Replaces `internal.DefaultChunkRendererCompatMixin` and
`internal.RenderSectionManagerCompatMixin` (group COMPAT).

## Problem

Chunk Animator (mod id `chunkanimator`) animates chunks as they appear: an ASM
coremod hooks vanilla's `RenderChunk.setOrigin` to start a chunk's clock and
`ChunkRenderContainer.preRenderChunk` to `glTranslate` the chunk while the
animation runs. Celeritas creates no `RenderChunk` and calls neither, so with
Celeritas installed the mod loads and does nothing: no chunk ever animates.

Celeritas draws each region with one cached multi-draw batch under one model
offset (`u_RegionOffset`), and `BatchAssembler` rebuilds the batch only when the
region's visible sections change. There is no place for a per-section
translation, and no hook a mod could use to ask for one.

## Proposal

A provider interface in `common`, registered with a static setter and inert
while none is set, as Actinium carried it ([Actinium PR #44](https://github.com/Q-Engineering-Source/Actinium/pull/44)):

```java
public interface ChunkAnimationProvider {
    default void onSectionAdded(RenderSection section) {}
    boolean getSectionOffset(RenderSection section, float[] out);
}
```

- `RenderSectionManager.onSectionAdded` reports the new section (the
  counterpart of `RenderChunk.setOrigin`).
- `DefaultChunkRenderer.render` asks the provider about each section with
  geometry when it (re)builds a region's cached batch. Sections with an offset
  are left out of the batch and drawn one by one after it, with the offset added
  to the region offset; the cached batch is marked as not reusable while any
  section of the region animates. Once nothing animates the full batch is cached
  again, so a region without animations costs nothing.

A per-draw offset uniform indexed by `_draw_id`, next to `celeritas_ChunkAges`,
would do the same in the shader without extra draw calls, at the price of a
second 256-entry uniform array in every terrain program (and in every shader
pack's terrain program under Iris).

## What Demonica drops

`DefaultChunkRendererCompatMixin`: a `@WrapOperation` on the
`BatchAssembler.createCachedBatch` call in `render`. While a provider is set and
reports an offset for a section of the region, upstream builds the cached batch
from a `ChunkRenderList` of the static sections only, and the mixin draws each
animating section with a one-section batch from `BatchAssembler.fillRegion`,
the region offset plus the animation offset as the model offset. The cached
batch then holds the shorter section list, so upstream's `CachedBatch.isValidFor`
fails against the full list on the next frame and the split is redone until
nothing animates. The animating sections are drawn just before the region's own
batch; for the sorted translucent pass that is a momentary change of order
within the region while the animation runs (about a second).

`RenderSectionManagerCompatMixin`: a TAIL injection on `onSectionAdded(III)V`
that hands the new section to the provider.

The provider itself (`com.demonica.celeritas.api.animation`) and
`ChunkAnimatorCompat`, which bridges it to Chunk Animator's `AnimationHandler`
with the `RenderSection` as the mod's identity token, stay in Demonica.
