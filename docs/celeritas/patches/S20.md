# S20: block quad transformers on the fast renderer

Draft, not sent. Replaces `seam.VintageBlockRendererQuadsMixin` (group DEGRADE).

## Problem

Demonica keeps Actinium's addon API `com.demonica.api.render.terrain.BlockQuadTransformer`:
addons register transformers that see a block's quads before they are meshed, to
add connected textures or emissive overlays without mixins into the terrain
renderer. Actinium called them from its own copy of the fast block renderer, after
the face culling test. forge122's `VintageBlockRenderer.renderBlock` has no hook
between the model's quads and the meshing of them.

Blocks on the vanilla path render through vanilla's `BlockModelRenderer` and never
reach the transformers, as in Actinium.

## Proposal

A transformer hook in `VintageBlockRenderer.renderBlock`, called with each face's
quads once the face passed `shouldSideBeRendered`, and with the unassigned quads.
Demonica's registry would register with it, or forward to an upstream registry if
Celeritas adopts one.

## What Demonica drops

The `@WrapOperation` on `IBakedModel.getQuads` in `renderBlock`. Because it wraps
the quad lookup, which comes before the culling test, it runs that test itself when
a transformer is registered, so a face culled anyway is not transformed. That is
one extra `shouldSideBeRendered` call per drawn face, and none when no transformer
is registered.
