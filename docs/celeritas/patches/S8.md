# S8: the terrain layers of a shader-pack frame

Draft, not sent. Replaces `seam.RenderGlobalTerrainMixin` (group CORE_TERRAIN,
together with S6m).

## Problem

forge122's `RenderGlobalMixin` `@Overwrite`s
`RenderGlobal.renderBlockLayer(BlockRenderLayer, double, int, Entity)`. Three
things are lost with the vanilla body:

1. **Third-party anchors.** Vanilla's four-argument method ends by calling the
   private one-argument `renderBlockLayer(BlockRenderLayer)`, and mods inject
   there. Distant Horizons anchors its deferred translucent LOD pass inside it;
   under Celeritas that pass never runs. This one has nothing to do with shaders.
2. **Layer phases.** A shader mod needs to know which terrain layer is being
   drawn, and before the translucent layer it runs its translucent prelude: the
   hand's solid parts are drawn and the pipeline switches to its translucent
   programs.
3. **Eye-relative drawing** under a pack; see [S6m](S6m.md).

## Proposal

1. In the overwrite, call the one-argument overload the way vanilla does, before
   the Celeritas draw. Its render container is empty under Celeritas, so it draws
   nothing, but the injections anchored in it run again. Demonica calls it for
   the translucent layer only (Distant Horizons' case); calling it for every
   layer would be closer to vanilla.
2. Call the provider around the draw: `beginTerrainLayer(layer, partialTicks)`
   before it, `endTerrainLayer(layer)` after it.
3. Add `provider.terrainEyeOffset()` to the camera Y passed to
   `drawChunkLayer` (with S6m's matching model-view).

Item 1 is worth proposing on its own.

## What Demonica drops

The HEAD and RETURN injections, the injection before `enableLightmap()` that
runs the one-argument overload, the `@ModifyArg` on the camera Y, and a
`@WrapOperation` around the `drawChunkLayer` call. The last three sit inside
upstream's overwrite and need a priority above upstream's 1000 on `RenderGlobal`
(Demonica uses 1100); the proposal removes that coupling. If either call site
inside the overwrite moves, its injector finds no target, which stops a dev run
(the injection audit, [`LEDGER.md`](../LEDGER.md#the-guard)).

The HEAD and RETURN pair is the fallback since the Moving Elevators fix
([`docs/compat/moving-elevators.md`](../../compat/moving-elevators.md)): the
phases are entered first at the `renderWorldPass` call site, around the call
(`EntityRendererIrisMixin`'s redirect of the four-argument method), and
`ShaderTerrain.beginLayer` returns false to a nested caller, whose `endLayer`
then does nothing. The pair still serves callers outside `renderWorldPass`
(GregTech CEu / Lumenized replace the translucent call with
`BloomEffectUtil.renderBloomBlockLayer`, which calls `renderBlockLayer` itself).

### Ordering

Mixin inserts every HEAD callback before the method's original first
instruction, processing mixins in priority order, so the lowest-priority
mixin's callback ends up first. Moving Elevators (priority 1000) draws its
moving cage at HEAD of the four-argument method; a HEAD injection at 1100 that
sets the phase runs after it, and lowering the priority would only move the
race. Item 2 of the proposal, if done as an `@Inject` at HEAD inside the
overwrite, would have the same problem: the provider calls belong around the
call, or at the start of the overwritten body as plain code, which a HEAD
injection still precedes. The call site is the only place that runs before
every HEAD injection.

The `@WrapOperation` is not part of the proposal: it is Demonica's own debug
tooling, through `RenderDebugHooks`, which the diagnostics jar implements.
With it installed and the GL debug option on, its `GlStateDiffProbe` logs the
GL state that changed across the draw and across the one-argument overload
(Distant Horizons' anchor), and the perf-debug report times each layer's draw
(`terrain-<layer>`). Both are no-ops without the diagnostics jar or while their
options are off. With
item 2 of the proposal, the provider's calls would give Demonica the same two
points.
