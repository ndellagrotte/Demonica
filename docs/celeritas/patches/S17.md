# S17: Celeritas's programs are not a mod's shader

No upstream change needed. Candidate for removal from the quarantine. Today:
`internal.GlProgramMixin` (group DEGRADE).

## What the patch does

While a pack's pipeline overrides shaders, Iris treats the bind of a program it
did not create as a mod's shader taking over the pass
(`IrisGLSMBridge`'s program-change listener): it drops its current pass and
re-applies it once the program is unbound. S17 registers every program Celeritas
links with `DepthColorStorage`, so these binds are not mistaken for a takeover.

## Why upstream is not needed

Under a pack, the programs that draw terrain are the pack's, and Demonica links
them itself (`IrisCeleritasChunkProgramOverrides.createShader`, through
`GlProgram.builder`). It can register each one there and unregister it in
`deleteShaders()`. Celeritas's own program is only used under a pack for a pass
the pack has no program for, and treating that as a takeover is correct.

A run without S17 (BSL, main pass over land, 2026-09-23) matched the frame with
it to a mean difference of 0.2/255. Before removing the patch, compare
translucent terrain and the shadow pass too.
