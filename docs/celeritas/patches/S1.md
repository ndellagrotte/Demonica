# S1: a shadow pass for the section manager

Draft, not sent. Replaces `internal.RenderSectionManagerMixin` (group SHADOW).

## Problem

A section manager has shadow render lists and a shadow search only when it is
built with `hasShadowPass = true`. forge122's `VintageRenderSectionManager` calls
the deprecated eight-argument constructor, which passes `false` on to the full
one (`RenderSectionManager.java:137-143`), so a shader mod on 1.12.2 can never
get Celeritas terrain into its shadow map. The modern loaders pass
`ShaderModBridge.areShadersEnabled()`.

## Proposal

Call the full constructor from `VintageRenderSectionManager`, with
`provider != null && provider.needsShadowPass()` as `hasShadowPass`
([README](README.md)).

## What Demonica drops

The `@ModifyArg` on the delegating `this(...)` call (index 8, static handler,
since it runs before the object is initialised).

## Notes

Demonica answers "yes" whenever a pack is active, as the modern loaders do,
even for a pack without shadows (its shadow lists stay unused). The answer then
changes exactly when the pass configuration (S14) does, so the renderer rebuild
that follows a pack change covers it. Reading it from the dimension's pipeline
instead would miss the pipeline at world load, which Iris prepares only on the
first frame, and cost a second rebuild at every world join.
