# S5: the pack's vertex format

Draft, not sent. Replaces the `chooseVertexType` injection in
`seam.CeleritasWorldRendererMixin` (group CORE_TERRAIN).

## Problem

forge122's `CeleritasWorldRenderer.chooseVertexType()` is private and picks
`VANILLA_LIKE` or `COMPACT` from an option. Shader packs need Iris's extended
format (block ID, mid-texture coordinate, normal, tangent). On the modern
loaders, `chooseVertexType()` returns Iris's `MODEL_VERTEX_XHFP` when
`WorldRenderingSettings.shouldUseExtendedVertexFormat()` says so.

## Proposal

```java
private ChunkVertexType chooseVertexType() {
    ChunkVertexType type = CeleritasVintage.options().performance.useCompactVertexFormat
        ? ChunkMeshFormats.COMPACT : ChunkMeshFormats.VANILLA_LIKE;
    ChunkVertexType override = provider != null ? provider.vertexType(type) : null;
    return override != null ? override : type;
}
```

The section manager fixes its vertex type when it is built. When the provider's
answer changes (a pack is loaded or unloaded), the provider is responsible for
calling `RenderGlobal.loadRenderers()`; Demonica's `ShaderTerrain.reloadIfStale`
already does.

## What Demonica drops

The HEAD-cancel on `chooseVertexType`.
