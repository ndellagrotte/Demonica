# I2: frame stamps that only increase

Draft, not sent. Replaces `internal.SimpleWorldRendererMixin` (group SHADOW).

## Problem

Each search stamps the lattice cells it visits with the `frame` its caller passes
in, and a cell is visited only if its stamp is older than the search's
(`OcclusionCuller.visit`, `state < frameStamp`). The terrain and shadow searches
keep separate visit state (`SectionLattice.visitState` and `shadowVisitState`),
but each still needs its own caller's frames to increase. Iris's shadow counter
restarts at 0 with every pipeline, while the section manager and its lattice can
outlive the pipeline (switching between packs with the same vertex format). The
shadow search then skips every cell it stamped before, until the counter catches
up, and shadow terrain goes missing. Any other caller whose counter goes
backwards has the same effect, for example a second renderer driving
`setupTerrain`.

Upstream already marks the `frame` parameters of `SimpleWorldRenderer.setupTerrain`
and `setupShadowTerrain` `@Deprecated(forRemoval = true)`.

## Proposal

Finish that deprecation: the section manager stamps both searches from one
counter it owns and increments per search, and ignores the callers' `frame`.

## What Demonica drops

The `@ModifyVariable(HEAD)` on both methods, and `DemonicaFrameClock`.
