# S7: Celeritas terrain in Iris's shadow pass

Draft, not sent. Replaces `internal.SimpleWorldRendererAccessMixin` (group
SHADOW); the adapter itself, `CeleritasWorldRendererCompat`, is Demonica's.

## What Demonica does

Iris's `ShadowRenderer` draws terrain through `WorldRendererCompat`.
`CeleritasWorldRendererCompat` adapts Celeritas's world renderer to it, and is
offered only while the section manager has a shadow pass (S1):
`updateForShadowPass` throws without one.

- **Order.** Upstream's protocol has the shadow pass run first in a frame:
  `setupShadowTerrain` runs the frame's terrain search along with the shadow
  search (which starts from the terrain search's visible set), and the terrain
  pass's `setupTerrain` reuses it (`RenderSectionManager.update`,
  `shadowPassRanThisFrame`). Demonica wraps vanilla's `RenderGlobal.setupTerrain`
  call in `EntityRenderer.renderWorldPass` and runs Iris's shadow pass just
  before it. Actinium ran the shadow pass after `setupTerrain`.
- **The player viewport** of the frame comes from the `ICamera` that
  `setupTerrain` is about to receive, since `getLastViewport()` still holds the
  previous frame's. The shadow pass restores it when it ends, so the shadow and
  entity frustums never leak into the terrain pass's visibility checks
  (Actinium left the entity frustum's viewport in place).
- **The spectator flag** is the player's, as vanilla passes it to
  `setupTerrain`. Iris passed `false`, and since this is now the frame's terrain
  search, a spectator camera inside a solid block culled everything behind it: in
  the Nether (2026-09-23), 1 visible section instead of 432.
- **Shadow block entities** (S18) come from the public
  `forEachVisibleBlockEntity`, while the manager is in its shadow pass (S3).

## What upstream would need

Two members of `SimpleWorldRenderer` that the adapter cannot reach:
- `currentViewport` is protected and set only by `prepareFrame`; the shadow pass
  sets it to its frustums and back. A public setter, or draw and visibility calls
  that take the viewport explicitly.
- `createChunkRenderMatrices()` is protected; the adapter needs it to draw several
  layers with each pass once (under pass consolidation, cutout and cutout-mipped
  share a pass). A public `drawChunkLayers(Collection<LAYER>, x, y, z)` that
  deduplicates passes would serve instead.

## Follow-ups (Demonica)

`ShadowRenderer` marks the section graph dirty every frame, and passes a camera
state that differs from the terrain pass's, so both searches run every frame.
Upstream searches only when the graph is dirty. Dirtying only the shadow lists
when the light or the shadow camera moves would restore that.
