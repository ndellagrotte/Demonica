# S11: vanilla-path quads carry their block context

Draft, not sent. Replaces `seam.VintageChunkBuildContextMixin` (group MESHING).

## Problem

`VintageChunkBuildContext.copyBlockData` reads the vanilla-path quads back from
each layer's `BufferBuilder` and pushes them into Celeritas's buffers, choosing the
material from the quad's sprite (`selectMaterial`,
`VintageChunkBuildContext.java:108-120, 133-168`). While a shader pack is active:
- The extended vertex encoder needs each quad's block context (the block's ID,
  whether it is a fluid, its light, its position in the section) before the quad
  is written. S10 records it per quad.
- Fluid quads (water, lava, and modded fluids of those materials) must mesh into
  the pack's water pass when they are translucent, since that pass writes depth,
  and must not be downgraded by the sprite analysis.

## Proposal

`copyBlockData` takes the layer's per-quad contexts (S10) and, for each quad:

```java
if (context != null && builder.getEncoder() instanceof ContextAwareChunkVertexEncoder encoder) {
    encoder.prepareToRenderVanilla(context);
}
Material material = context != null && context.isFluid()
    ? provider.fluidMaterial(configuration, layerMaterial)   // S14's water pass
    : selectMaterial(layerMaterial, sprite);
builder.getVertexBuffer(facing).push(quad, material);
// then finishRenderingBlock() on the same encoder
```

This needs a context-aware encoder interface in `common`, as the modern loaders
have in `modern` (`ContextAwareChunkVertexEncoder`), and a fluid material on the
provider or on `RenderPassConfiguration` (see S14).

## What Demonica drops

The three `@WrapOperation`s: on the `copyBlockData` call in
`convertVanillaDataToCeleritasData` (hands over the layer's contexts), on
`selectMaterial` (fluid material), and on `ChunkMeshBufferBuilder.push` (prepares
and finishes the encoder around each quad).
