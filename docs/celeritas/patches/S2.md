# S2: shader-pack programs for terrain passes

Draft, not sent. Replaces `internal.ShaderChunkRendererMixin` (group CORE_TERRAIN).

## Problem

`ShaderChunkRenderer.begin(TerrainRenderPass)` always compiles and binds
Celeritas's own `blocks/block_layer_opaque` program for the pass
(`ShaderChunkRenderer.java:123-146`). A shader mod has no way to draw a pass with
the pack's program instead. On the modern loaders Iris is compiled in; forge122
has no equivalent.

## Proposal

Let `begin` ask the registered `TerrainShaderProvider` (see [README](README.md))
first:

```java
protected void begin(TerrainRenderPass pass) {
    pass.startDrawing();
    var override = provider != null ? provider.program(pass, this.renderPassConfiguration) : null;
    if (override != null) {
        this.activeProgram = override;        // the provider owns its lifetime
        override.bind();
        override.getInterface().setupState(pass);
        return;
    }
    ... // unchanged
}
```

`end` needs no change: it already calls `restoreState()` and `unbind()` on
whatever `activeProgram` is. The hook lives in `common`, so every loader gets it.

## What Demonica drops

The HEAD-cancel pair on `begin`/`end`, and `ShaderTerrain.packProgram`'s role as
the patch's entry point (it becomes the provider method).
`AnchorInventoryTest.forge122DoesNotOverrideTheSeamHooks` guards the current
patch: an override of `begin`/`end` in forge122's `$ChunkRenderer` would bypass it.
