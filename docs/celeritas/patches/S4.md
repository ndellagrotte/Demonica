# S4: fog occlusion under shader packs

Draft, not sent. Replaces `seam.VintageRenderSectionManagerMixin` (group DEGRADE).

## Problem

With `useFogOcclusion` on, the terrain search stops at vanilla's fog cutoff
(`RenderSectionManager.getSearchDistance`). A shader pack that turns vanilla fog
off draws its own fog, usually farther out, so the search drops sections the
pack still shows. The modern loaders already handle this:
`ModernRenderSectionManager.useFogOcclusion()` returns false whenever shaders are
enabled (with a `TODO: does *every* shaderpack really disable fog?`).
forge122's `VintageRenderSectionManager.useFogOcclusion()` has no such check.

## Proposal

Mirror the modern rule in forge122, through the provider:

```java
protected boolean useFogOcclusion() {
    return CeleritasVintage.options().performance.useFogOcclusion
        && !(provider != null && provider.isShaderPackActive() && FOG_SERVICE.getFogMode() == ChunkFogMode.NONE);
}
```

Demonica's rule is the narrower one above: fog occlusion stays on for a pack
that keeps vanilla fog, which answers the modern code's TODO. Upstream may prefer
the modern loaders' simpler rule.

## Inert today

While S15 applies, S4 changes nothing. S15 reports planar fog, and upstream's
fog occlusion never shortens a search under planar fog: both searches call
`getSearchDistance(null)`, and the planar case needs a projection matrix to bound
the view cone (`RenderSectionManager.java:1022-1031`), so it falls back to the
render distance. S4 takes effect if S15 fails, or reports another shape.

## What Demonica drops

The HEAD-cancel on `useFogOcclusion`. The rule is the same for the terrain and
shadow searches.
